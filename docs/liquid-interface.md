# BELLO 전역 인터페이스 검수

기준 브랜치는 `design/bello`다. 검수에는 샘플 옷장과 매번 새로 연 독립 브라우저 컨텍스트를 사용했다. 아래 경로의 화면 적용 여부와 공급자 연결 여부는 별개다. [공식 디자인 명세](https://app.notion.com/p/425aaf785efc81bfbe71cdf1095c8639) · [기능·연동 매트릭스](../REQUIREMENTS.md)

## 사용 흐름

홈 왼쪽 위 BELLO를 누르면 누른 위치에서 공간 이동 화면이 펼쳐진다. 가까운 조형물을 누르거나 가로로 끌어 공간을 고른다. 화살표와 들어가기 버튼으로도 같은 동작을 수행한다. 전체 기능 검색은 상태 화면까지 찾는다. 색인은 선택한 공간의 기능을 보여 준다. 공간 내부에서는 상단의 현재 위치, 이전 화면과 관련 작업을 이용한다.

## 공통 구현

| 조작 | 적용과 실제 상태 |
| --- | --- |
| 내비게이션 | `BelloAtlas`, `SpaceCarousel`, `RoomNavigation`이 공간·현재 경로·검색을 공유한다. 이동은 기존 해시 URL을 사용한다. |
| 버튼·탭·카테고리 | `Control`은 사진과 스와치의 원래 색을 유지한다. 확정과 보조 동작은 서로 다른 재질을 쓰며 `Segment`의 곡면은 선택한 항목의 실제 위치와 너비를 따라 이동한다. |
| 입력·검색·슬라이더·토글 | `Field`와 `TextArea`는 원래 입력 이벤트·레이블·브라우저 유효성 검사와 IME를 유지한다. 수치 조절에는 값에 연동된 트랙을, 음성 설정에는 스위치를 사용한다. |
| 셀렉트 | `Choice`가 필드 위나 아래의 남은 공간을 계산한다. 선택하면 기존 select의 change 이벤트가 발생한다. 화살표·Home·End·Enter·Escape와 포커스 복귀를 지원한다. 파일·날짜·색상 선택은 기기의 전용 선택기를 연다. |
| 모달·알림·진행·오류 | 공통 `Sheet`는 네이티브 dialog에 광학 조작부를 결합한다. `Feedback`, 상태별 토스트, 실제 요청 중의 aria-busy를 사용한다. 데이터 저장소 초기화와 재시도는 기존 이벤트를 따르고 전역 스타일로 표시한다. |
| 광학·모션 | 곡면 법선으로 만든 SVG 변위 필터, WebGL 장면의 굴절 렌더 타깃, 터치 좌표에 따른 반사, 스프링 기반 공간 선택, BELLO 상태별 SVG 형태를 사용한다. 화면 전체에 변위 필터를 씌우지 않는다. |
| 드레스룸 | 비대칭 런웨이와 반사 날개를 GLB로 수록했다. 의류 미리보기 완료 후 스캔이 실제 의류 윤곽을 따라간다. 일반 의류 사진 착장은 정면 2D 미리보기다. 별도 모델 치수 도식과 실사 피팅 요청이 있다. |
| 렌더링 비용 | WebGL을 지연 로드한다. 픽셀 예산·DPR 상한과 장시간 느린 프레임의 해상도 하향을 적용한다. 정지 시 렌더링을 멈추고 WebGL이 준비되면 보조 Canvas 렌더러도 멈춘다. 감소된 모션과 WebGL 비지원 경로가 있다. |

브랜드 재질은 Optical White, Silver Blue, Lavender, Hologram, Deep Slate, Midnight 토큰을 참조한다. 오류·경고·성공은 의미 전용 토큰을 사용한다. 사진·피부·머리·상품·사용자가 고른 배색은 별도다.

## 브라우저에서 확인한 결과

- Chrome에서 320×700, 375×812, 390×844, 430×932, 768×1024, 1280×800, 844×390을 확인했다. 각 크기에서 아래 55개 URL을 직접 열었다. 최종 385회에서 페이지 JS 예외와 가로 넘침이 없었고, 각 main 내부의 버튼·입력·select에는 공통 컴포넌트 속성이 있었다.
- 첫 모바일 검수에서 발견한 헤더 줄바꿈, 쇼핑 설명·버튼 충돌, 스타일링 화면 가로 5px 넘침을 수정했다. 가로 모드의 저장 버튼 하단은 수정 전 456px, 수정 후 385px로 390px 뷰포트 안에 들어왔다.
- 실터치 프로토콜로 두 손가락 확대와 공간 드래그를 확인했다. 메뉴 전환 중 조형물 위치의 서로 다른 표본 27개를 기록했다. 320px 전체 메뉴의 측정 대상은 가장 작은 타깃도 44×44 CSS px 이상이었다. 기본 라이트 모드에서 비활성 작업 링크의 배경 대비는 5.47:1, 본문과 배경은 11.97:1이었다.
- Mac Chrome의 390px/기기 픽셀비 2 에뮬레이션에서 룸은 526×1139 렌더 표면, 15 draw calls, 삼각형 18,484개였다. 입력이 멎은 뒤 500ms 동안 추가 WebGL draw 호출은 0이었다. 메뉴 드래그 1회에서 39 프레임 간격의 중앙값은 16.7ms, p95는 17.1ms였다. 실기기 전체 성능을 대표하지 않는 단일 관측이다.
- WebGL 생성을 차단한 새 컨텍스트에서 대체 오브젝트·공간 선택이 동작했다. 모션 감소, 다크 모드, 모달 안의 선택창, Escape와 포커스 복귀, 예산 정렬 및 키보드 선택을 확인했다. 카메라 권한 거절 후 합성 미디어 스트림으로 재시도해 촬영 목록 1장을 확인했다.
- `interface-check.mjs`에서 옷 끌어 입히기·고정·저장, 검색과 상세, 치수 보존, 키보드 공간 탐색을 확인했다. `service-check.mjs`에서 다중 사진, 사진 원본, 코디 재열기, 링크와 이메일 가져오기, 모드 간 격리를 확인했다. `backup-check.mjs`에서 이전 백업, 중복 방지, 손상된 항목 롤백, 원본 내보내기를 확인했다.
- 이 검수에는 실제 iPhone의 Safari, 하드웨어 카메라, 발열, 배터리 소비량이 포함되지 않는다. 일반 사진 의상의 리깅·천 시뮬레이션과 유료 생성 품질도 미검증이다. API·DB·개인정보 전송 계약 변경은 이 디자인 변경에 포함되지 않는다.

## 브랜치 경계

운영 기준은 `main`, 이전 드레스룸은 `design/dressing-room`이다. Astra의 `feature/bello-product-ai`와 Claude의 `design/claude-spatial`은 독립 검수 대상이다. Claude 전용 공간 프로토타입은 해당 브랜치에 있다. 이 작업은 두 브랜치에 병합하지 않았다.
