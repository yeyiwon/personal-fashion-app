# BELLO · 개인 AI 드레스룸

의류를 직접 등록하고, 실제 보유한 옷으로 코디를 구성하고, 개인 모델과 피팅 보드에서 다음 착장을 준비하는 모바일 우선 서비스다. 기존 웹과 iOS 앱에 사용하던 IndexedDB를 그대로 연다. 첫 방문은 샘플 21벌로 시작한다. 기존 의류나 코디가 있으면 개인 옷장을 먼저 연다.

[운영 서비스](https://personal-fashion-app.vercel.app/) · [전체 요구사항과 44개 화면 대조](./REQUIREMENTS.md) · [외부 연동과 데이터 범위](./docs/integrations.md) · [샘플 이미지 출처](./docs/sample-visuals.md)

## BELLO 전역 인터페이스

드레스룸의 BELLO 조작부에서 공간을 선택한다. 각 공간의 관련 작업, 옷 등록, 코디와 프로필은 같은 입력·선택 시스템을 사용한다. 실행은 `npm run dev:local`이다. [공간 이동](http://127.0.0.1:5188/#/tools) · [55개 경로·모바일 검수](./docs/liquid-interface.md) · [대표 화면](./docs/bello-mobile.webp)

## 이전 드레싱룸 디자인 프리뷰

`design/dressing-room`은 운영 기준 커밋 `a5c3f9b`에서 분기했다. 홈의 옷을 눌러 상세를 열거나 코디·피팅 영역에 끌어 놓을 수 있다. 옷장은 분류별 레일과 검색 목록으로 전환한다. 개인 모델의 부위 표시를 누르면 해당 치수의 눈금자와 회전 가능한 도식이 열린다. 모든 화면의 **공간 이동**에서 여섯 목적지에 접근한다. 모델 생성·피팅 공급자와 로컬 데이터 스키마는 기존 구현을 사용한다. 프리뷰와 운영 주소의 브라우저 저장 공간은 각 출처(origin)에 귀속된다.

## 실행

Node 22.12 이상이 필요하다.

```sh
npm ci
npm run dev:local
```

웹 개발 주소는 `http://127.0.0.1:5188`이다. 서버는 로컬 인터페이스에만 바인딩한다. 개발 서버와 Vercel은 같은 `/api/weather`와 `/api/shopping` 핸들러를 사용한다. 전체 메뉴와 주요 화면을 해시 경로로 직접 열 수 있다.

## 데이터와 연결 경계

개인 옷장은 `personal-fashion-wardrobe` 버전 1의 garments, images, outfits, profile 저장소를 쓴다. 이미지 한 장과 메타데이터를 같은 트랜잭션으로 저장하고, SHA-256 인덱스로 같은 파일을 검출한다. 코디의 의류 참조는 저장 시 확인한다. 코디에서 사용 중인 의류는 먼저 코디에서 빼야 삭제할 수 있다. 이미지 원본과 EXIF는 기기에 남으며 내보내는 JSON에는 원본 사진이 포함된다.

샘플 카탈로그는 앱에 포함된 파일에서 읽는다. 샘플 코디 편집본과 활동 기록은 `wardrobe.studio.v2.sample.`, 개인 활동 기록은 `wardrobe.studio.v2.personal.` 아래 보관한다. 등록·복원·삭제 화면에는 작업 대상 옷장이 표시된다. 실제 계정 간 동기화는 별도 구현 범위다.

원본 사진·도식·기본 착장 사진과 사용자가 고른 의류 목록을 구분한다. 외부 생성 공급자에 요청을 보내지 않은 상태에서 착용 결과나 청구 이력을 만들어내지 않는다. 화면별 이용 범위는 **전체 메뉴 → 기능별 이용 범위**에서 확인한다. 날씨는 도시를 선택한 뒤 사용자 요청으로 조회한다. 제휴 검색에는 운영자의 별도 승인·키가 필요하다.

## 디자인과 플랫폼

홈은 실제 룩 사진과 같은 의류의 컷아웃을 연결한다. 레일에서는 터치 스크롤로 대상과 배경 시점이 함께 이동한다. 의류를 살펴보면 같은 객체와 하단 조작부가 확대되고, 현재 옷의 편집 동작을 제공한다. 조작부는 배경의 명암과 의류색을 비추며 텍스트 뒤에는 대비를 유지한다. 직접 코디에서는 터치·키보드로 옷의 위치를 바꾼다. 브라우저가 View Transitions를 지원하면 같은 객체를 보간하고 모션 감소 설정에서는 즉시 전환한다.

별도 iOS 타깃은 같은 번들을 WKWebView에서 연다. `npm run build` 후 `python3 generate-ios.py`와 Xcode로 실행한다. 웹용 공급자 함수는 오프라인 네이티브 번들에 포함되지 않는다. 자세한 네이티브 빌드 절차는 [iOS 문서](./IOS.md)에 있다.

## 검증

`npm run build`는 strict TypeScript와 프로덕션 번들 생성을 실행한다. 로컬 서버를 띄운 뒤 `APP_TEST_URL=http://127.0.0.1:5188 npm run test:flow`로 별도 브라우저 프로필에서 회귀를 검사할 수 있다. 실제 등록 데이터가 있는 브라우저 프로필로 삭제·복원 시험을 실행하지 않는다.

2차 개편에서는 기존 0.1.0 서비스 화면에서 PNG 두 장과 코디를 저장한 뒤, 같은 origin과 브라우저 프로필로 새 번들을 열었다. 개인 모드가 자동 선택됐고 의류 두 벌의 원본 기반 미리보기와 저장한 조합을 다시 열었다. 또한 직접 코디의 고정·개별 교체와 룩북 JPEG 다운로드를 검증했다. 작은 화면의 가로 넘침과 데스크톱 화보의 얼굴 잘림은 브라우저 검사 후 수정했다.

2026-11-27 로컬 서버에서 53개 경로를 320·390·768·1280px 너비로 열었다. 212회 모두 경로를 찾았고 가로 넘침이나 페이지 예외가 없었다. 홈의 크롭 트렌치 태그에서 의류 상세로 이동한 뒤 공간 옷장에서 같은 의류를 피팅 보드로 전달했다. 구매 링크, `.eml`, 예시 쇼핑몰 동의·중복 제외, 개인/샘플 격리와 손상 백업 롤백도 별도 브라우저 프로필에서 확인했다. 서울 실시간 예보는 36개 시점을 반환했다. iOS는 실기기용 Release 번들의 미서명 빌드까지 확인했고, 카메라와 제스처의 실제 iPhone 검수는 남아 있다.
